# LBJ-行业分析 — 端到端行业研究 Skill

给一个行业名称，产出一份**所有数字都能回溯到来源**的交互式 HTML 行业研究报告（10 章 + 附录 A–D）。不是"帮你写篇分析"，而是把行业研究的完整流程——边界界定、数据采集、回源核验、产业链拆解、竞争格局、情景预测、结构门禁——固化成一条可重复执行的流水线。

## 安装

```bash
git clone https://github.com/youyituomaoxian/laobanjiu-skills.git
cp -r laobanjiu-skills/LBJ-行业分析 ~/.workbuddy/skills/LBJ-行业分析
```

或下载 zip → 解压到 `~/.workbuddy/skills/LBJ-行业分析/`。安装后重启 WorkBuddy 即可。

## 使用

```
分析一下国内短剧出海行业
做一份储能行业的研究报告
新能源车行业的市场规模和竞争格局怎么样
LBJ-行业分析 工业机器人
```

**不需要填参数、不需要选模板。** 把行业名称说出来就行——skill 会自行判断一个合理的口径并显式声明，不会停下来反复问你。

### 产出

```
output/{行业名}/
├── {行业名}_analysis_{年份}.html   主报告（浏览器直接打开，10 章 + 4 附录）
├── {行业名}_dataset.csv            采集到的原始数据
└── {行业名}_sources.md             来源清单 + 回源核验记录
```

### 不适用

- 单只股票或基金的行情与估值判断 → 走金融数据类 Skill
- 单篇财报解读
- 无研究交付要求的泛泛介绍（"XX 是做什么的"）

## 设计原理

### 第一性原理：行业研究真正难的不是"找不到数据"，而是"找到的数据不可信"

行业报告的失败模式几乎从不表现为"没内容"，而表现为**内容看起来很像那么回事，但数字互相矛盾、来源无法回溯、口径偷偷混用**。

拆到最底层的约束，只有三条是硬的：

1. **模型不知道任何行业的真实数字。** 训练数据里的行业数字必然过期、必然有错、必然缺口径。所以任何"凭印象写出来的数字"都是负资产——它比空白更有害，因为读者无法分辨。
2. **同一个指标在真实世界里就有多个互不兼容的口径。** 这不是数据源不专业，而是统计边界本身就不同（是否含 IAA、是否含港澳台、App 内购还是全产业）。**口径分歧是行业的客观属性，不是数据缺陷。**
3. **单次采集必然出错。** 子代理会给出错的财务数字、错的日期、错的归属关系。这不是偶发故障，是必然概率事件。

因此本 Skill 的三条设计主线全部由这三条约束反推而来：

| 底层约束 | 对应设计 |
|---|---|
| 模型没有可信记忆 | **绝不编造数字**。查不到就写「未找到公开来源」，数字位留空，绝不做估算填补 |
| 口径分歧是客观属性 | **强制输出口径分歧矩阵**，把冲突摊开而不是掩盖 |
| 单次采集必然出错 | **主 Agent 回源核验 + 可执行的结构门禁** |

### 为什么"先界定边界"必须排在"找数据"之前

这是全流程最反直觉、也最关键的一步。

如果先找数据再收敛口径，你会得到一堆"看起来相关"的数字，然后被迫在写作阶段用模糊话术缝合它们——"据不同机构统计,规模在 30–40 亿美元之间"。这句话掩盖了真正有信息量的内容：**为什么差了 10 亿美元？差在哪三处边界上？**

反过来先把 7 项边界钉死（行业定义 / 分类代码 / 聚焦环节 / 地理范围 / 时间边界 / 核心指标 / 易混邻近行业），后续所有数据都被迫在同一把尺子下对齐，分歧才会以"干净的形式"暴露出来——而干净的分歧是可以被定位、被解释、被转引的。

### 为什么门禁必须写成脚本而不是 checklist

一份 10 章、90 KB 的 HTML 报告，人工核对 28 项结构约束（图表计数、锚点对应、标签配对、元信息齐全、附录分节、裸色、金额币种……）在第一次大概能做到，第三次开始必然漏。

更关键的是：**能自动查的东西靠肉眼查，等于把可靠性交给了当天注意力。** 所以 Stage 9 被实现为 `scripts/validate-report.mjs`——零依赖、可重复、退出码可判定。它第一次跑真报告就抓出了 3 处人工遗漏的真缺陷（header 缺两项元信息、附录未按 A–D 分节、来源表 4 处金额省掉币种）。

这条循环还反向约束了 Skill 自身的演进：**检查项出现误报时收紧正则，而不是删掉检查。**

## 工作流

| Stage | 内容 | 强制产出 |
|---|---|---|
| 0 | 行业界定 | 7 项边界声明 |
| 1 | 数据采集 | 4 路子代理并行分治（规模 / 竞争 / 产业链 / 政策资本） |
| 2 | 规模与增长 | **口径分歧矩阵** |
| 3 | 产业链与利润池 | 环节毛利率区间 + 利润池分布 |
| 4 | 竞争格局 | CR4/CR8/HHI + 波特五力 + 上市公司财务对照 |
| 5 | 供需与成本 | 供需平衡表 + 周期位置判断 |
| 6 | 驱动因素 | PESTEL + 政策时间线（≥10 条，核到发布机构） |
| 7 | 情景预测 | 三情景（概率合计 100%）+ 触发信号 + 敏感性分析 |
| 8 | 生成报告 | 10 章 + 附录 A–D |
| 9 | 门禁与校验 | `validate-report.mjs` 全绿 |

### 六条不可协商的数据纪律

1. **绝不编造数字** — 查不到就写「未找到公开来源」
2. **回源核验** — 主 Agent 亲自回源一次，重点核①上市公司财务②份额排名③企业归属；警惕双源引用同一错误原文造成**循环印证**
3. **先界定边界再谈数据** — 7 项钉死
4. **强制口径分歧矩阵** — 区分「看似矛盾」与「真正冲突」
5. **货币与单位统一** — 主币种唯一、换算标汇率时点、**禁用换算值做同比**、禁写裸「亿」
6. **可信度逐项标注** — ★★★ / ★★ / ★ /【估算】

## 报告视觉规范

默认 **弘讯暗色**（preset A）—— 令牌取自弘讯 B 端设计系统 `tokens.json` 的 `dark` 节（`generatePalette('#005EAE',{mode:'dark'})` 引擎输出）。
页面底 `#121826` / 卡片 `#1E293B` / 抬升面 `#243044` / 品牌深表面 `#0A2540` / 主色 `#3B82F6` / 辅调青 `#38BDF8`。

已内置的备选预设：**preset B** hot-analysis 深藏蓝紫（`--bg:#0b0f19` / `--accent:#a78bfa`）、**preset C** shadcn Zinc 深灰。切换只需替换令牌块，元素与组件不变。

只换色值不会得到这套风格——真正决定"像不像"的是十个标志性元素：**Hero banner 底（品牌深表面渐变 + 点阵纹理 + 双层 radial 光晕）**、渐变标题、36×36 编号徽章、**品牌深蓝毛玻璃 sticky 导航（结构骨架走 `--brand-surface`，避免"亮蓝壳 + 深色芯"）**、功能色柔底提示框、`✦` 摘要盒、11px 大写表头、回到顶部、等宽数字 `tnum`，以及弘讯专属的第 10 条「品牌深表面骨架」。全部细节见 `references/报告风格与组件规范.md`。

配色遵循中国金融市场惯例 **红涨绿跌**（`--up:#FF4D4F` / `--down:#52C41A`），与欧美相反。

**动效层（原生零依赖，无 React / 无 Framer Motion）**——参考稿里的效果被翻译成 `IntersectionObserver` + rAF 节流的 scroll 监听：

| 效果 | 落点 |
|---|---|
| 滚动显影 FadeIn | 各 section 标题 / 表格 / 图表盒 / 卡片，子项带 stagger |
| 字符级逐字显影 | 01 执行摘要的 5 条核心结论（`opacity .2 → 1`） |

全部挂在 `html.js-anim` 下：**无 JS 或系统开启「减弱动效」时自动全部失效**，内容照常可见；`@media print` 里已强制还原，未滚动过也能正常导出 PDF。

`assets/report-shell.html` 是报告外壳骨架，内含 6 个图表槽位，覆盖全流程所有图表要求：

| 槽位 | 类型 | 用途 |
|---|---|---|
| `c-market` | 柱 + 折线双轴 | 规模与增速 |
| `c-share` | 横向条形 | 竞争份额 |
| `c-cr` | 折线 | CR4/CR8 集中度演变 |
| `c-five` | 雷达 | 波特五力 |
| `c-price` | 折线（历史/预测分色） | 价格走势 |
| `c-scenario` | 多线 | 三情景路径 |

## 校验器

```bash
node scripts/validate-report.mjs output/{行业名}/{行业名}_analysis_{年份}.html --strict
```

| 选项 | 作用 |
|---|---|
| `--strict` | 把提醒升级为失败（交付前必开） |
| `--framework` | 声明框架版，放行「待采集」占位（无联网降级时用） |
| `--out <文件>` | 把报告写入文件（终端 stdout 静默的环境必须用它） |
| `--json <文件>` | 输出机器可读结果 |
| `--quiet` | 只列问题 |

28 项检查分四类：

- **完整性** — 占位符残留、待填标记、非法字符（U+FFFD / 零宽 / 私有区）
- **一致性** — canvas 数 ↔ `new Chart()` 数、canvas id 是否被引用、导航数 ↔ section 数、锚点可达、章节编号连续、标签配对与 div 开闭平衡
- **规范性** — 10 章必备章节、附录 A–D 分节、header 元信息六项、免责声明、可信度徽章、动效降级、表格横向滚动、`.tw` 容器、`aria-hidden`、令牌外裸色、金额缺币种的裸「亿」
- **时效性** — 数据截止距报告生成是否 >90 天

## 无联网降级

CDP 未授权、搜索全部失败时，**降级产出框架版**：照常输出 10 章结构与附录骨架，所有数字位留空并标注 `待采集`，报告头部显式声明本版为框架版并列出恢复采集的步骤。

**绝不**用记忆性知识填充数字——即使标注估算也不做。

---

## 已知限制

- **依赖联网。** 无网时只能出框架版，不出数据。
- **不覆盖付费墙内容。** 部分行业的权威数据在付费报告里，此时该指标会进入「未找到公开来源清单」而非被估算。
- **政策类信息需回源。** 二手转载的日期错误率相当高（实测案例中，两份政策文件的日期在转载链上都错了），必须核到发布机构官网或权威法源。
- **校验器只管结构，不管内容真伪。** 它能保证报告结构完整、单位规范、骨架无误；数字是否属实只能靠 Stage 1–2 的回源核验纪律。**门禁全绿 ≠ 内容正确。**

## 迭代记录

本 Skill 的方法论随实跑演进，"发现缺口 → 改真源 → 升版本号 → 补进 SKILL.md"是它的核心竞争力；视觉层则随弘讯设计系统演进。

| 版本 | 主题 | 新增 |
|---|---|---|
| v1.1 | **数据可信层** | 口径分歧矩阵（强制）、回源核验硬规则、基线差异 >20% 禁给单点增速、子代理分治策略、强制附录 B/C |
| v1.2 | **报告可用层** | 货币与单位统一、可信度分级强制标注、子赛道拆分规则、术语与缩写表、数据质量评分、元信息头（六项口径元信息）、时效性声明、图表最小必要原则 |
| v1.3 | **视觉与交付契约层**（非实跑驱动） | 默认风格换为**弘讯暗色**（映射 tm-design-system `dark` 令牌 + 第 10 条「品牌深表面骨架」）、Hero banner 底、tab 居中、报告头部取消「修订记录」模块、动效两件套（滚动显影 / 字符级显影）、圆角字号字体对齐弘讯令牌阶 |

v1.1 / v1.2 两轮实跑共修出 16 项；v1.3 为使用者指定的视觉层修订。实跑样例：国内短剧出海行业（34 个来源，10 图表，116 表格行，`--strict` 28 PASS / 0 WARN / 0 FAIL）。
