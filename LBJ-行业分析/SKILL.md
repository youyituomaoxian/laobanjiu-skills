# LBJ-行业分析

把「一个行业名称」变成「一份可回溯的交互式行业研究报告」。

## 何时使用

用户表达下列任一意图时启用：

- 「分析一下 XX 行业」「帮我做 XX 行业的研究报告」
- 「XX 行业的市场规模 / 竞争格局 / 产业链 / 集中度怎么样」
- 「XX 行业有什么机会和风险」「XX 行业未来怎么走」
- 显式点名：`LBJ-行业分析`、`行业分析`

**不适用**：单只股票或基金的行情与估值判断（走金融数据技能）；单篇财报解读；泛泛的「介绍一下 XX」（无研究交付要求）。

## 核心纪律（不可协商）

以下六条来自两轮实跑修订，是这份 skill 区别于「随便写个行业报告」的全部价值所在：

1. **绝不编造数字。** 每个数字必须来自实际打开读到的来源。查不到就写「未找到公开来源」，不做估算填补。
2. **回源核验。** 任何写进报告主体的数字，主 Agent 必须**亲自回源核验一次**——重点是①上市公司财务 ②份额/排名 ③企业归属关系。子代理输出只当线索。注意双源可能引用同一错误原文造成**循环印证**。
3. **先界定边界，再谈数据。** 行业定义、分类代码、聚焦环节、地理范围、时间边界、核心指标、易混邻近行业——7 项钉死并声明全文统一口径。
4. **强制输出口径分歧矩阵。** 同一指标多来源冲突时，输出「来源 × 数值 × 口径边界 × 可信度」表，逐条定位分歧成因，区分「看似矛盾」与「真正冲突」。
5. **货币与单位统一。** 主币种唯一，换算必须标汇率与时点，**不得用换算值做同比**。金额写 `亿美元`／`亿元`，禁止只写「亿」。
6. **可信度逐项标注。** ★★★（双独立源交叉验证）/ ★★（单一权威源）/ ★（存疑）/【估算】（推算，须独立标注）。

## 标准工作流

### Stage 0 · 行业界定
锁死上述 7 项。用户未指定时自行判断一个合理口径并显式声明，**不要停下来反复确认**。

### Stage 1 · 数据采集
**并行派出子代理分治**（目标独立、子任务量足够大时）：

```text
子代理 A：市场规模与增长（规模、增速、地区结构、渗透率）
子代理 B：竞争格局（玩家名单、份额、集中度、龙头财务）
子代理 C：产业链与成本（环节拆解、成本结构、利润池、爆款率/回本率）
子代理 D：政策与资本市场（政策原文、监管、上市公司、融资并购）
```

下发给子代理的指令必须包含三句数据纪律，能显著降低编造率：

- 每个数字要标 `来源 + URL + 发布时间 + 口径`
- 找不到可靠来源就写「未找到公开来源」
- 不确定的归属关系写「未核实」

同时对子代理声明：**描述目标而非步骤**，避免用「搜索/爬取」这类暗示手段的动词，否则会把子代理锚定到错误路径。

需要浏览器层时（公众号等反爬平台、需登录态），加载 `web-access` skill。CDP 未授权不阻塞：公开数据用 WebSearch / WebFetch 静态通道即可覆盖大部分需求。

### Stage 2 · 规模与增长
先出**口径分歧矩阵**，再谈数字。历史基线多源差异 >20% 时禁止给单点增速，改给区间并把冲突年份在图表中留空。

### Stage 3 · 产业链与利润池
上中下游拆解 → 每环节标注主要玩家／毛利率区间／议价能力／进入壁垒 → 利润池分布与最厚环节 → 瓶颈环节。成本与利润率数据优先取上市公司财报。

### Stage 4 · 竞争格局
玩家名单（≥10 家）+ 份额 + **CR4/CR8/HHI** + 龙头财务对比 + 近 2–3 年份额演变 + 投融资。波特五力逐项给「强/中/弱」+ 事实依据。
若行业含多个子赛道，按纪律要求**拆分后再汇总**（分解之和须等于合计，汇总增速须加权）。

### Stage 5 · 供需与成本
供给（产能/产量/利用率）｜需求（终端结构/下游景气）｜库存｜价格走势与周期位置｜成本曲线。做供需平衡表，判断产能周期阶段。

### Stage 6 · 驱动因素
PESTEL 逐项给「方向 + 强度 + 文件/数据依据」。政策时间线 ≥10 条，每条标日期 + 文件名原文 + 影响方向。政策类信息必须核到发布机构官网或权威法源。

### Stage 7 · 情景预测
三情景（概率合计 100%），每个给量化目标 + **可观测的触发信号**。加敏感性分析（对结论影响最大的 2–3 个变量，±20% 波动测试）。预测必须显式标注为预测。

### Stage 8 · 生成报告
以 `assets/report-shell.html` 为基底，写入 `output/{行业名}/{行业名}_analysis_{年份}.html`，含：

1. 执行摘要（5 条核心结论，**每条必带数字**）
2. 行业界定与口径说明（含子赛道拆分）
3. 市场规模与增长（含口径分歧矩阵 + 趋势图）
4. 产业链与利润池（含结构图）
5. 竞争格局（含份额图 + 五力雷达图 + 上市公司财务对照表）
6. 供需与价格（含平衡表 + 价格走势图）
7. 驱动因素（含政策时间线）
8. 情景预测（含三情景对比图）
9. 风险提示与免责声明
10. 附录 A 数据来源清单 ｜ 附录 B 口径分歧矩阵 ｜ 附录 C 未找到公开来源清单 ｜ 附录 D 术语与缩写表

壳内已备 **6 个图表槽位**，覆盖上述全部图表要求：`c-market` 规模趋势（柱+折线双轴）、`c-share` 竞争份额（横向条形）、`c-cr` 集中度（折线）、`c-five` 五力（雷达）、`c-price` 价格走势（折线，历史段/预测段分色）、`c-scenario` 三情景（多线）。不需要的槽位**整段删除**（`<canvas>` 与其 `new Chart(...)` 调用必须成对删）；确有额外图表价值时按图表最小必要原则自行增补。

**报告头部元信息**（必须有，且必须置于 `<header>` 内）：口径基准 / 分析周期 / 数据截止 / 报告生成 / 主币种与汇率时点 / 来源数。数据截止与报告生成差距 >90 天须说明原因。**报告头部不设「修订记录」模块**——若做过订正，留痕写在交付说明里，不进报告正文。

### Stage 9 · 门禁与校验

```bash
node scripts/validate-report.mjs output/{行业名}/{行业名}_analysis_{年份}.html --strict
```

选项：`--strict` 把提醒升级为失败（交付前必开）；`--framework` 声明框架版（放行「待采集」）；`--out <文件>` 把报告写入文件（**终端 stdout 静默的环境必须用它，再读文件**）；`--json <文件>` 输出机器可读结果；`--quiet` 只列问题。

脚本会查 28 项，覆盖四类：

- **完整性**：占位符残留、待填标记、非法字符（U+FFFD / 零宽 / 私有区）
- **一致性**：canvas 数 ↔ `new Chart()` 数、canvas id 是否被引用、导航数 ↔ section 数、锚点可达、章节编号连续、标签配对与 div 开闭平衡
- **规范性**：10 章必备章节、附录 A–D 分节、header 元信息六项齐全、免责声明、可信度徽章存在、动效降级、表格横向滚动、`.tw` 容器包裹、`aria-hidden`、令牌外裸色、金额缺币种的裸「亿」、`prefers-reduced-motion`
- **时效性**：数据截止距报告生成是否 >90 天

**未全绿不得宣告完成**，并列出未通过项。结构全绿后再跑质量门禁三层清单与数据质量评分（扣分表见模板第七节），**同时给出评分与扣分明细**。

## 无联网降级

CDP 未授权、搜索全部失败等导致无法采集数据时，**降级产出框架版**：

- 照常输出 10 章结构与附录骨架
- 所有数字位置留空并标注 `待采集`
- 报告头部显式声明「本版为框架版，数据未采集」，并列出恢复采集的具体步骤
- **绝不**用记忆性知识填充数字（即使标注估算也不做）

## 输出约定

```text
output/{行业名}/
├── {行业名}_analysis_{年份}.html      主报告
├── {行业名}_dataset.csv              采集到的原始数据（如有）
└── {行业名}_sources.md               来源清单 + 核验记录
```

## 常见失败模式

| 失败模式 | 表现 | 对策 |
|---|---|---|
| 编造数字 | 出现无来源的具体数字 | 停下，回到 Stage 1 补采 |
| 循环印证 | 两个来源其实是同一原始出处 | 追到最上游出处，确认独立性 |
| 口径混算 | 不同口径数字直接相除算增速 | 建口径分歧矩阵后重算 |
| 单位错误 | 人民币/美元、亿元/亿美元混用 | 全文主币种唯一 + 标汇率时点 |
| 子赛道污染 | 用全行业平均利润率代表某子赛道 | 拆分后分别给利润率 |
| 图表堆砌 | 图很多但没有一张不可替代 | 「删掉这张，读者损失哪个判断？」 |
| 预测当事实 | 预测值未标注 | 预测段落独立标注 |

## 迭代

本 skill 的方法论真源是 `references/行业分析提示词模板.md`。**每次实跑后若发现新缺口，直接修订该模板并升版本号**，然后把新缺口与修复补进 SKILL.md 的纪律或工作流——两轮实跑（v1.0→v1.1→v1.2）共修出 16 项，这个自审循环是本 skill 的核心竞争力。

`scripts/validate-report.mjs` 是这条循环的自动化部分：能自动查的绝不靠肉眼。它自己也会随实跑演进——若某类缺陷反复逃过检查，就把它加成新的检查项。反向也成立：检查项出现误报时应收紧正则而不是删掉检查（例如「亿」缺币种的检查从「一律报」收紧为「命中金额语境词才报」，避免把「18 亿用户」误判为金额）。
